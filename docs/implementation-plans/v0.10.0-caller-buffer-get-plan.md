**Stage C review findings and correction contract** (source lines refer to `d232f18`):

1. **C-F1, P1 — Azure can accept an oversized blob's prefix as the whole object.**
   `azure_client.rs:614–634,1200–1215` treats a response without `Content-Range` as a whole-object
   response. If a proxy strips that header from a 206, a request for N bytes of a larger blob
   returns length N and incorrectly succeeds. `tests/azure_get_into_fake.rs:967–983` currently
   asserts that success. This is an exact-length contract failure, not an acceptable recorded
   limit. The correction should request **checked N+1 bytes**, with `parallel=1` and
   `partition_size=N+1`, while the destination and expected whole-object size remain **N**.
   Zero length still requests one byte. An exact blob ends at N; a larger blob exposes at least
   N+1 when the requested range is honored even if the range header is stripped. Validate headers
   before copying and never write the extra byte. Reject overflow before submission. The pinned
   SDK computes the remaining range using `min(request_end, resource_len)`, so an exact blob still
   takes the direct-body, no-partition-buffer path. No SDK fork is required. Invert the recorded-limit
   test to require a mismatch, zero progress and an untouched destination; retain exact/short/long,
   zero-length, canary, request-shape and allocation-control tests. This is the reviewed amendment
   to §4.3's N-byte request shape, not a change to caller-buffer semantics.
2. **C-F2, P1 — `mkdir_async` reintroduces attachment outside the exit-safe bridge.**
   `python_core_api.rs:2603` calls `Python::attach` on the Tokio worker after the I/O completes,
   before the delivery gate acquires its ticket. A late completion can therefore attach after
   the shutdown drain has closed the gate, reintroducing the class of finalization race addressed
   by #192. Return a Rust value such as `Ok(None::<()>)`; the pinned PyO3 `Option<T>` conversion
   produces Python `None` inside the existing gated delivery. Do not replace this with another
   ungated attach/check. Preserve the awaited `is None` test and add a bounded late-completion/
   shutdown regression that distinguishes the old attachment path from gated conversion.
3. **C-F3, P2 — bound total GCS repair work, including SDK resumption.**
   `google_gcs_client.rs:1944–1956` resets the repair counter whenever any bytes arrive. One byte
   followed by failure can produce one reconnection per object byte and reset backoff repeatedly,
   retaining the caller allocation for excessive time. Use a finite total repair budget per logical
   read that does not reset with progress (a separate no-progress limit may remain). The real
   `HttpOpener` at `2244–2259` also inherits the pinned SDK's bare `Recommended` resume policy:
   `storage/common_options.rs:34` has no attempt decorator, and `read_resume_policy.rs:134–140`
   ignores the resume count. Merely capping the outer loop does not cap this inner path. Apply an
   explicit per-request policy on the **new** receive path via `with_read_resume_policy`: either
   disable SDK resumption and let the bounded outer loop own repairs, or use a finite SDK limit
   and document/test the combined bound. Preserve existing read APIs and the fork pin. Test
   repeated one-byte failures beyond the total budget, exact request counts, retained progress,
   generation pinning and release on terminal failure. Include the real opener with its production
   resume policy, not only a test-only override that disables the SDK layer.
4. **C-F4, P2 documentation — qualify HEAD absence.**
   `python_core_api.rs:2433–2436` and the trait HEAD documentation still promise a missing bucket
   always raises. Match the actual reviewed semantics: S3's bodyless HEAD 404 and GCS `NotFound`
   can mean an absent bucket or object, so both may return `None`; a distinguishable Azure missing
   container remains an error. Keep 403 and other failures as errors. No extra bucket-listing or
   existence probe is required to manufacture a distinction the response does not provide.

## 1. Scope and decisions

**In this round:**

1. **New public APIs for S3 (including S3-compatible services), Azure Blob and native GCS**, behind
   one provider-neutral interface:
   - `object_capabilities`, `get_into_async`, `head_async`;
   - the `ObjectMetadata` type;
   - three exceptions (§4.1).
   GCS is supported both natively (`gs://`) and through GCS's S3-compatible endpoint (`s3://` with a
   custom endpoint). Test order is S3, then Azure, then GCS. That is test order only; every provider
   ships in this release.
2. **Reuse** the released borrowed PUT, exact DELETE, client caches, export-release infrastructure
   and the exit-safe async bridge. No copied GET adapter, no PUT replacement, no separate native
   extension for a consumer.
3. **Selected fixes:** #235, #224, #263 (all five timestamp sites), #261, #250, #233, #230, and the
   existing six-file privacy scrub commit `39da876`.
4. **Version 0.10.0:** a new public API surface plus tightened input and URI validation. One
   integrated release candidate; no series of small releases.

**Decided out of scope:**
- **GCS Rapid SDK modernization and write-path redesign.** No fork migration (#257) or vendored SDK
  changes. Rapid in its existing state remains supported. Adapting the existing s3dlio read and
  metadata routes to the new caller-buffer and typed-HEAD APIs **is in scope** (§4.3); it does not
  require the deferred SDK port.
- Downstream benchmark tooling and its pin upgrades are a later round.
- Public file/direct caller-buffer GET, a native batch GET, broader LIST semantics,
  MultiEndpointStore logging (#175), replay or op-log schema redesign (#176, #185, #214), bounce-pool
  tuning, and GCS wheel expansion on PyPI.

**Agreed clarifications:**
- **Logical GET byte count** = the distinct destination positions filled. Not wire bytes, not
  retries, not "valid data". Progress is kept on partial failure (§4.4).
- **Azure receives through a checked loop** over the public response-body stream, not the SDK's
  `collect_into`. That helper returns early on a mid-stream error and loses the partial count (§4.3).
- **Unpinned responses are never combined.** Without a usable version identity, a successful single
  response is accepted. A partially received request fails rather than being repaired or retried
  from pieces of unknown versions (§4.3).

## 4. Design

### 4.1 Public interface

```text
object_capabilities(uri) -> {"provider": str, "get_into": bool, "head": bool}
get_into_async(uri, dst, *, expected_len) -> guarded awaitable[int]
head_async(uri) -> guarded awaitable[ObjectMetadata | None]

ObjectMetadata: frozen {size: int >= 0, etag: str | None, version_id: str | None}
ObjectNotFoundError(FileNotFoundError)
LengthMismatchError(ValueError)   # .expected, .actual (None if unknown)
UnsupportedOperationError(NotImplementedError)
```

- **Existing APIs stay stable**, except for the selected fixes, which are documented compatibility
  notes:
  - #261 rejects int, bool and non-buffer iterables as PUT payloads;
  - #224 rejects an empty Azure container;
  - #233 makes `mkdir_async` return None.
- **Unsupported builds or providers refuse clearly.** They never fall back to a temporary download
  plus copy.
- **Capabilities in this round:**
  - true for S3 and Azure in native-backend builds that include them, and for native GCS using the
    official pinned SDK in the full build, including its existing Rapid route;
  - false for file://, direct:// and any compiled-out provider;
  - no automatic true result for an alternative Arrow or legacy `gcs-community` implementation
    merely because its provider scheme exists. Those implementations do not acquire these new
    operations in this round; report their actual support and preserve their existing APIs.

  They are computed without credential discovery or client initialization; pure parsing is extracted
  where needed.
- **Object keys are literal:** `%2F` stays three characters.
- **Rust side.** An additive receive method on `ObjectStore` takes a borrowed `&mut [u8]` destination
  and defaults to unsupported, so existing external implementations need no new required method. A
  default proves no wider compatibility. `LoggedObjectStore` and every wrapper the Python store cache
  uses override and forward it.
- **Errors.** A small shared typed-error and metadata representation, not a new error hierarchy.
  - **S3:** extend `SdkFailure` to keep the status and service code next to its retry verdict, or
    classify at the typed request boundary.
  - **Azure:** reuse `AzureRequestError` and `BlobNotFound`.
  - **GCS:** keep the typed gax status and HTTP status on the new paths.

### 4.2 Writable ownership and completion

1. **Validation.** Accept only a writable, C-contiguous byte export: itemsize 1, format `None`/`B`/
   `b`/`c`, optionally with one byte-order prefix (`@=<>!`), so the byte formats the borrowed PUT path accepts (including ctypes byte arrays) are accepted here too; PUT also accepts other non-pointer formats, which this writable destination refuses.
   Pointer-bearing or object formats are rejected. `0 <= expected_len <= nbytes`, with
   checked conversions.
2. **Preparation failures** release the export synchronously, then raise.
3. **Handle first.** The guarded completion handle exists before any native write starts. From then
   on, every outcome goes through the handle. PUT's post-spawn wrapper-construction window is not
   reproduced.
4. **Exclusive use.** Native code has exclusive use of the destination span until terminal. The
   documentation forbids reading, modifying, resizing or reusing it before then. A held export blocks
   resizing; it cannot block a racing writer or DMA.
5. **One barrier.** Success, error, cancellation and retries all converge on the same release
   barrier. Terminal means every native writer has stopped and the export has been released with a
   valid Python token. The existing exit-safe delivery gate and releaser rules apply: the GIL is never
   acquired from an arbitrary native `Drop`.
6. **No detached mutable addresses.** Use structured receive futures and disjoint borrowed slices.
   A child that cannot be cancelled keeps its ownership until it really finishes.
7. **Cancel semantics** match the released `GuardedFuture`. `cancel()` is True while the inner future
   is pending, and the handle then ends cancelled. It is False once the outcome is fixed, and the
   handle then ends with that outcome.
8. **HEAD** has no payload, but uses the same quiescence completion, so callers can bound outstanding
   native work.

"Zero copy" means no extra whole-object allocation or copy between s3dlio and the caller. SDK and
network chunks are still written into the final destination. GET must not use `get()` plus a copy,
a zero-filled full-size master buffer, or `ReadBuffer` accumulation plus a copy.

### 4.3 Providers

| Provider | Receive and consistency | Metadata and errors |
|---|---|---|
| **S3** (AWS and S3-compatible, including GCS's S3 endpoint) | Covers all three routes: global-client small GET, concurrent ranges, per-endpoint clients. Streams chunks into the destination. **Range fan-out:** a fresh HEAD on every call, ignoring the size cache, for size and ETag; `If-Match` on every range and retry; each retry's cursor reset; returned range bounds and total validated; a 412 fails the logical read. **HEAD fails or supplies no usable ETag:** one GET, pinned to its first-response ETag for any retry; a known size mismatch is still an error. **If that first response also carries no ETag,** a partially received request fails; a retry is allowed only before any byte has been written. **A pinned ranged or retry response that carries no ETag fails** (it cannot confirm the version), and is not retried. | Keeps HTTP status and service code. ### 4.4 Logging and byte counts

- New GET and HEAD calls go through the cached store and logger. The wrapper forwards the receive
  method explicitly, so a trait default can never make a logged store look unsupported or skip the
  log.
- **One logical GET is one GET row**, including after a failure or cancellation once native work has
  started, with the actual outcome. Internal ranges, retries and size-probe HEADs are not extra rows.
  An explicit `head_async` is its own HEAD row.
- **The byte count** is the distinct destination positions filled. Each fixed, disjoint span keeps a
  high-water mark, and the marks are summed, so a retried span is not counted twice. Progress
  survives errors and cancellation. On failure the count says which positions were touched, never
  that the data is valid.
- The TSV/zstd schema and the row-ownership rules are unchanged. These rows are logical calls, not
  an HTTP/RPC request trace.

**A2. Typed errors** (new `src/object_error.rs`)

```rust
pub enum ObjectErrorKind {
    NotFound,
    LengthMismatch { expected: u64, actual: Option<u64> },
    VersionChanged,
    Unsupported,
    Forbidden,
    Throttled,
    Transport,
    Server,
    Other,
}
pub struct ObjectError { pub kind: ObjectErrorKind, pub provider: &'static str, message: String /* redacted */ } // Display + Debug + Send + Sync + 'static
impl std::error::Error for ObjectError {}
pub fn object_error(err: &anyhow::Error) -> Option<&ObjectError>
```

- **Attached as context:** `anyhow::Error::context(ObjectError{..})` over the retained SDK error, at
  every attachment site.
- **Lookup is `err.downcast_ref::<ObjectError>()`.** anyhow's context-aware downcast finds a
  context payload at any depth. Walking `err.chain()` never yields it, because a context layer
  appears there as a private `ContextError` type.
- **One lookup rule everywhere.** `object_error`, the Python exception mapping, `RetryClassify` and
  `delete_contract::is_not_found` all use this lookup. A source-chain walk remains only as the
  fallback for errors that carry no `ObjectError`.
- **The outermost semantic classification is authoritative.** A `VersionChanged` attached over an
  SDK 404 stays `VersionChanged`. The SDK error stays recoverable for diagnostics, but never
  overrides it.
- **Retry verdicts:**
  - `RetryClassify` reads `ObjectError` first. NotFound, VersionChanged, Forbidden, LengthMismatch
    and Unsupported are not retryable.
  - For every other kind (Throttled, Transport, Server, Other), and when no `ObjectError` is
    present, today's verdict is unchanged: the `SdkFailure` verdict where one exists, otherwise
    retried (the existing conservative default).
  - A generic retryable source never overrides an outer non-retryable `ObjectError`.
  - This compatibility fallback is not the retry predicate for the new GCS loop; its narrower
    typed-only rule is specified below. Existing retry call sites retain their behavior.
- **`is_not_found` follows the outer classification.** When an `ObjectError` is present, it returns
  true only for `NotFound`. A `VersionChanged` over a GCS or Azure 404 is therefore not "not found".
  Without one, the existing typed chain check runs unchanged.
- **S3 classification is code-first,** preserving today's `status_is_retryable` order for ordinary
  failures. The pinned-read identity-loss override below takes precedence over this table:
  1. A code accepted by `is_transient_error_code` (the AWS throttling and transient tables plus
     `S3DLIO_EXTRA_TRANSIENT_CODES`, including `ExpiredToken` and `RequestExpired`) is retryable
     even on a 403. A throttling-table code → `Throttled`; any other transient code → `Server`.
  2. The code `NoSuchBucket` → Other (a missing bucket is an error, not object absence, matching
     Azure); then 404, `NoSuchKey` or `NotFound` → NotFound.
  3. 412 → VersionChanged.
  4. Any remaining 403 (e.g. `AccessDenied`) → Forbidden.
  5. 429 or 503 → Throttled; 408 or any other 5xx → Server.
  6. A failure with no HTTP response (connect, timeout, body stream) → Transport (an SDK construction failure → Other).
  7. Anything else → Other.

  `SdkFailure` gains `status: Option<u16>` and `code: Option<String>`, filled in the generic
  `sdk_anyhow<E>` from `raw().status().as_u16()` and `err().code()`.
- **Azure:** `AzureRequestError` gains a crate-visible `error_code()` from `azure_core::Error`'s
  `ErrorKind::HttpResponse`. Mappings:
  - `BlobNotFound` → NotFound; `ContainerNotFound` → Other;
  - 412 → VersionChanged; 403 → Forbidden;
  - 429 and 503 → Throttled.

  Body-stream errors are mapped through `auth_err` (SAS redaction).
- **GCS:** the new paths keep `google_cloud_gax::error::Error` with
  `anyhow::Error::new(e).context(..)`. Mappings:
  - `http_status_code() == 404` or `status().code == NotFound` → NotFound;
  - 412 or `FailedPrecondition` → VersionChanged;
  - 403 or `PermissionDenied` → Forbidden;
  - `Unavailable` and `ResourceExhausted`, or 503 and 429 → Throttled;
  - 408, `Internal` and `Aborted` → Server; `DeadlineExceeded` → Transport; `Unknown`, `Cancelled`
    and `Unauthenticated`/401 → Other (not retried).

  **The new GCS retry and repair loop uses a typed-only predicate,** not the existing
  message-text helper (`is_retryable_gcs_read_error`) or the generic conservative fallback.
  Only outer `Throttled`, `Transport` and `Server` classifications are retryable. Transport and
  body failures must be classified from their typed sources; an unclassified error, `Other`, or
  message text containing a status number does not authorize a retry. Existing receive/version
  rules still apply: this verdict never authorizes combining unpinned responses.
- **A pinned read never reports absence.** Once an ETag or generation is pinned, a 404 on any later
  retry, range or repair is attached as **`VersionChanged`**. `NotFound` comes only from the first
  request, or from HEAD.
- **Existing APIs keep their error behavior.** `is_not_found`'s acceptance of `NotFound` is additive.

**A4. Writable export** (`src/python_api/put_payload.rs`, reusing its barrier)

```rust
pub(crate) struct WritableExport { owner: ExportOwnerMut }
pub(crate) fn acquire_writable(py: Python<'_>, dst: &Bound<PyAny>, expected_len: usize, latch: &Arc<Latch>) -> PyResult<WritableExport>
impl WritableExport {
    pub(crate) fn as_mut_slice(&mut self) -> &mut [u8]; // exactly expected_len; `&mut []` when 0
    pub(crate) fn release(self, py: Python<'_>);        // direct release, no queue
}
```

- **One latch.** The caller creates one `Arc<Latch>`. The same latch goes to `prepare_guard` and
  `acquire_writable`; the guard and the export never wait on different latches.
- **Request:** `RawExport::get(data, flags)` (it already takes flags) with
  `PyBUF_WRITABLE | PyBUF_FORMAT | PyBUF_C_CONTIGUOUS`, and no read-only fallback. Then check:
  - `readonly == 0`;
  - `itemsize == 1`; format `None`, `B`, `b` or `c`, optionally with one byte-order prefix (`@=<>!`), so the byte formats the borrowed PUT path accepts (including ctypes byte arrays) are accepted here too; PUT also accepts other non-pointer formats, which this writable destination refuses; `format_has_pointers` refusal;
  - `expected_len <= len`, and a non-null `buf` when `len > 0`.

  A failed check releases the export, then raises.
- **Zero length:** `as_mut_slice` returns `&mut []` without calling `from_raw_parts_mut`. A null
  pointer is invalid even for length 0.
- **`release(py)`** mirrors `ExportOwner::release`: `PyBuffer_Release` and `mark_released`, then
  `mark_dropped`, using the current Python token and no queue. It is used for every failure before
  ownership transfers (A5).
- `ExportOwnerMut`'s `Drop` matches `ExportOwner`'s: queue push, `mark_dropped`, nothing on a
  finalized interpreter. That `Drop` is the path once native code owns the export.
- **Reused unchanged:** `Latch`, `latch_ready`, `quiesce_*`, the `ReleaseQueue`, the releaser,
  `AttachGate`/`begin_shutdown`, the stats. `RawExport`'s `Sync` safety comment is updated.

**A5. Handle-first completion** (`src/python_api/python_core_api.rs`; `future_into_py` unchanged)

**GET (`get_into_async`):**
1. `object_capabilities(uri)`. If `get_into` is false, raise `UnsupportedOperationError`
   synchronously.
2. Build the store on the caller thread with `py.detach(|| get_or_create_store(&uri, global_logger()))`
   (#173). `get_into_async` and `head_async` are both added to the store-cache test.
3. `let latch = Latch::new();` then `prepare_guard(py, latch.clone())`.
4. `acquire_writable(py, dst, expected_len, &latch)`.
5. Create `(tx, rx) = oneshot::channel::<WritableExport>()`. Then
   `inner = future_into_py(py, async move { let mut owner = rx.await?; store.get_into(&uri, owner.as_mut_slice(), &progress).await … })`.
   - `owner` is declared before the `get_into` future, so it drops after every writer.
   - The task holds no buffer until step 7.
6. `guard = PreparedGuard::instantiate(py, inner)`, which does not wait. `wrap_in_guard` is not
   used: its error path waits on the latch.
7. `tx.send(owner)`. On `Err(owner)` (the receiver has gone), release it directly, cancel the guard
   and raise. **Once the send succeeds, nothing fallible remains:** the guard is returned, and every
   later outcome belongs to it and its release barrier.

A failure in steps 1–4 holds no export (A4 releases before raising) and raises directly.

**Pre-transfer failure path** (any error in steps 5–7 before a successful send):
- drop `tx`;
- `owner.release(py)` directly, without queueing and without `quiesce_blocking`;
- cancel `inner` or the guard if it exists, ignoring any exception from cancelling, which never
  blocks the release;
- raise the **original** error.

The buffer is reusable immediately. No quiescence timeout is possible, and no
`ExportStillReferencedError` is raised.

**Cancellation and panics.**
- pyo3-async-runtimes' `Cancellable` ends the Rust future when `inner` is cancelled. That drops the
  `get_into` future, which stops every writer, and then `owner`, whose `Drop` marks the latch. If the
  task never received `owner`, dropping the receiver drops it from the channel through the same
  `Drop`.
- The guard's terminal state waits for `latch_ready`.
- A panic is delivered by the existing panic path.

**HEAD (`head_async`):**
- Capability check on `head`, not `get_into`. The store is built on the caller thread, as in GET
  step 2.
- A **unit permit** start channel, `oneshot::channel::<()>()`.
- A `HeadQuiescence` token (holding the latch) is constructed before `future_into_py` and moved into
  the future. It is the **first** local bound in the future body, so it drops after any native
  request future.
- Its `Drop` calls `mark_dropped()` then `mark_released()`, with no GIL. It therefore marks
  quiescence when:
  - the unpolled future is dropped;
  - bridge creation fails (the future is dropped);
  - the start channel closes;
  - the request finishes, is cancelled, or panics.
- The guard is instantiated with `PreparedGuard::instantiate`, then `tx.send(())` releases the
  request. `wrap_in_guard` is not used.
- **Pre-start failure:** if `future_into_py` or `instantiate` fails, or the send fails, `tx` is
  dropped, `inner` is cancelled (ignoring cancel errors) and the original error is raised. The token
  marks the latch when the future drops. Nothing waits on the latch.
- No step waits for an event-loop callback that it itself prevents.

**Results and errors** (via `object_error`, A2):
- `get_into_async` returns `int(expected_len)`.
- NotFound → `ObjectNotFoundError`.
- LengthMismatch → `LengthMismatchError`, with `.expected` and `.actual` set by `setattr`.
- Unsupported → `UnsupportedOperationError`.
- Everything else → the existing `py_err`.

**Python surface:**
- `create_exception!` with `PyFileNotFoundError`, `PyValueError` and `PyNotImplementedError` bases;
- `#[pyclass(name = "ObjectMetadata", frozen, eq, hash)] struct PyHeadMetadata { size, etag, version_id }`
  with `#[pyo3(get)]` fields and `__repr__`;
- registered in `register_core_functions`; re-exported by the `dir(_core)` loop.

**A6. Logging** (`src/object_store_logger.rs`)

- **One completion-aware `CallRow` drop guard** (new, recording through the existing `record_call`)
  serves both new methods. Each writes **exactly one** row.
- **GET:**
  - normal return records the outcome, with `bytes = progress.filled`, which can be non-zero with an
    error;
  - `Drop` without completion records `error = "cancelled"` and the current `progress.filled`;
  - `first_byte` comes from `progress.first_byte`, or `end`.
- **HEAD:**
  - success records `bytes = size`;
  - absence is a successful row with bytes 0;
  - an error is an error row with bytes 0;
  - a cancelled HEAD is `error = "cancelled"` with bytes 0;

    on success, absence, error and cancellation, including helper rows.
- **S3 helper rows:** `S3ObjectStore::get_into` and `head` honor `self.rows()`. A helper-row store
  writes its own row, under the same GET and HEAD rules as above. Otherwise the wrapper's row is the
  only one. Internal ranges, retries, repairs and the fan-out HEAD write no rows.

**A7. Progress accounting**

- Each **fixed, disjoint** destination span (the whole object, or one range part, fixed when the
  read starts) keeps one high-water mark. **The mark persists across every retry and repair of that
  span.**
- After each copy, if the new end exceeds the mark, the delta is added to `progress.filled` and the
  mark moves. The first non-empty copy sets `first_byte`.
- A retry restarts the cursor at the span start, and adds nothing until it passes the mark.
- A GCS tail repair writes the **suffix of the same span**, resuming at the cursor (at or below
  the mark). It is never a new, separately counted span.

## 9. Acceptance gates

### Lifetime and correctness

- **Lengths and buffers:** exact, short and long objects; a zero-length destination and object;
  malformed lengths; non-contiguous, read-only and wrong-format exporters; checked overflow; canaries
  beyond `expected_len`. A failure never publishes partial contents.
- **No extra copy:** the destination address equals the caller allocation's address; allocation size
  is checked, not padded capacity. No second full-object allocation, zeroing pass or SDK partition
  accumulation on any supported path.
- **Writes and cancellation:** held native writes; partial receive failure; retries; cancellation
  before the first poll, during receive and after the result is fixed; repeated `Task.cancel`,
  `wait_for` and `asyncio.timeout`. The export is released before every terminal state, including
  preparation and launch failures and an already-terminal handle.
- **PUT regressions:** the release-barrier and atexit tests stay green.
- **Python versions:** CPython 3.11–3.13. No free-threaded or wider claim without separate
  verification.
- **Capabilities:** with credentials absent and client construction forbidden, nothing reaches a
  provider. Compiled-out and unsupported implementations report False. Ordinary versus Rapid GCS
  routing is resolved during actual I/O, never by a network probe in `object_capabilities`.

### Providers

- **Error classes:** typed absence versus forbidden, throttling, transport and server failures. A
  missing Azure container is not object absence. Zero, negative or missing sizes are checked
  explicitly, with no `unwrap_or(0)`.
- **S3:**
  - the first-response ETag;
  - a fresh HEAD per range call despite a warm or stale size cache;
  - `If-Match` on every range and retry; a 412 and a missing ETag handled;
  - range header validation;
  - a same-size overwrite during fan-out;
  - retry cursor reset;
  - endpoint routing, with no global-client leakage.
- **Azure:**
  - exact, oversized and undersized blobs;
  - 200 and 206 lengths; the empty-blob 416;
  - ETag consistency;
  - checked-loop counts on short, overflow, error and cancellation;
  - the no-remaining-ranges path verified by allocation inspection, not only by the options.
- **GCS:**
  - HTTP and gRPC receive;
  - a partial read plus tail repair;
  - a same-size overwrite, with generation reuse;
  - Rapid-aware metadata, including empty objects;
  - Rapid-bucket `get_into` works through the existing route, including tail repair with the
    generation pinned.

  The fork pin is unchanged.
- **Every provider:**
  - PUT from real caller memory, HEAD, GET into another real allocation, then byte comparison;
  - exact DELETE and already-absent DELETE;
  - keys with literal `%2F`, `%`, `@`, `=`, nested prefixes and a trailing dot;
  - no listing used to find objects.
- **Logging on and off:** exactly one logical GET or HEAD row, the correct outcome and count on
  partial failure and cancellation, and no duplicate helper rows. Existing PUT and DELETE logging is
  preserved.

### Build and release

- **Pre-push gate** (CLAUDE.md), all clean:
  - `cargo fmt --all -- --check`;
  - `cargo clippy --lib --bins --examples -- -D warnings`;
  - `cargo test --lib`;
  - the same clippy and test runs with `--features extension-module`, since `src/python_api/`
    changes.
  - Zero crate-local warnings, and no underscore-prefix silencing.
- **Before any PR** (CLAUDE.md):
  - the wheel built with `./build_pyo3.sh`;
  - `uv run pytest` of the in-repo suite against that wheel;
  - for `python/` changes: `ruff check python/`, `ruff format --check python/`, and
    `uv run python -m compileall -q python/s3dlio python/tests`;
  - a real Python caller-buffer consumer smoke with the candidate wheel installed, including
    address identity, cancellation and content checks. The existing data-loader smoke recommended
    by CLAUDE.md is additional coverage when coordinated; it is not a substitute for exercising the
    new receive API, and does not authorize changing any consumer's code or dependency pins.
- **Rust checks:** formatting, clippy, and unit and targeted integration tests for the default,
  extension-module and full-backend builds. The Arrow library is checked separately if shared
  interfaces change. Never `--all-features`.
- **Wheels:** `./build_pyo3.sh` builds them, and the installed wheel is what gets tested, with the
  imported path, version and features recorded (ephemerally) to rule out source shadowing. Every
  Python command runs through `uv run ... python`.
- **Baseline:** if the whole suite is not green, baseline failures are re-established against 0.9.128
  in the same environment and compared by test identity and reason. A skipped cloud test never counts
  as provider validation.
- **Capabilities by build:** the default wheel reports S3 and Azure; the full build also reports
  native GCS. x86_64/aarch64 and CPython 3.11–3.13 packaging are kept.
- **After functional approval:** caller-buffer GET is measured against the existing allocating GET at
  identical sizes and concurrency, including memory and GIL progress. Destination memory is kept
  separate from staging, and request concurrency from range fan-out. No hardware-specific default is
  introduced.
