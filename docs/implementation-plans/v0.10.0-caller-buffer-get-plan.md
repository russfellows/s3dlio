# s3dlio v0.10.0 plan: caller-buffer GET, typed HEAD and selected fixes

**Status:** the single living plan for this round, updated in place. It is agreed when the
maintainers approve the current text. Approval authorizes the bounded implementation in §7. It does
not authorize a push, PR, tag or publication; each of those needs an explicit maintainer
instruction.

**Location and privacy.** This file is in the public s3dlio repository. It describes the s3dlio
feature generically, for any consumer that owns its buffers. Downstream integration details stay
private and are not referenced here. No hostnames, accounts, credentials or private repository
names appear in this file.

## 1. Scope and decisions

**In this round:**

1. **New public APIs for S3 (including S3-compatible services), Azure Blob and native GCS**, behind
   one provider-neutral interface:
   - `object_capabilities`, `get_into_async`, `head_async`;
   - the `ObjectMetadata` type;
   - three exceptions (§4.1).
   GCS is supported both natively (`gs://`) and through GCS's S3-compatible endpoint (`s3://` with a
   custom endpoint). Test order is S3, then Azure, then GCS. That is test order only; every provider
   ships in this release.
2. **Reuse** the released borrowed PUT, exact DELETE, client caches, export-release infrastructure
   and the exit-safe async bridge. No copied GET adapter, no PUT replacement, no separate native
   extension for a consumer.
3. **Selected fixes:** #235, #224, #263 (all five timestamp sites), #261, #250, #233, #230, and the
   existing six-file privacy scrub commit `39da876`.
4. **Version 0.10.0:** a new public API surface plus tightened input and URI validation. One
   integrated release candidate; no series of small releases.

**Decided out of scope:**
- **GCS Rapid storage changes.** No Rapid SDK or fork migration (#257), and no Rapid write-path work;
  these need work outside s3dlio. Rapid buckets remain supported by the existing code paths. §4.3
  states the read-path rule.
- Downstream benchmark tooling and its pin upgrades are a later round.
- Public file/direct caller-buffer GET, a native batch GET, broader LIST semantics,
  MultiEndpointStore logging (#175), replay or op-log schema redesign (#176, #185, #214), bounce-pool
  tuning, and GCS wheel expansion on PyPI.

**Agreed clarifications:**
- **Logical GET byte count** = the distinct destination positions filled. Not wire bytes, not
  retries, not "valid data". Progress is kept on partial failure (§4.4).
- **Azure receives through a checked loop** over the public response-body stream, not the SDK's
  `collect_into`. That helper returns early on a mid-stream error and loses the partial count (§4.3).
- **Unpinned responses are never combined.** Without a usable version identity, a successful single
  response is accepted. A partially received request fails rather than being repaired or retried
  from pieces of unknown versions (§4.3).

## 4. Design

### 4.1 Public interface

```text
object_capabilities(uri) -> {"provider": str, "get_into": bool, "head": bool}
get_into_async(uri, dst, *, expected_len) -> guarded awaitable[int]
head_async(uri) -> guarded awaitable[ObjectMetadata | None]

ObjectMetadata: frozen {size: int >= 0, etag: str | None, version_id: str | None}
ObjectNotFoundError(FileNotFoundError)
LengthMismatchError(ValueError)   # .expected, .actual (None if unknown)
UnsupportedOperationError(NotImplementedError)
```

- **Existing APIs stay stable**, except for the selected fixes, which are documented compatibility
  notes:
  - #261 rejects int, bool and non-buffer iterables as PUT payloads;
  - #224 rejects an empty Azure container;
  - #233 makes `mkdir_async` return None.
- **Unsupported builds or providers refuse clearly.** They never fall back to a temporary download
  plus copy.
- **Capabilities in this round:**
  - true for S3, Azure, and native GCS in builds that include it;
  - false for file://, direct:// and any compiled-out provider.

  They are computed without credential discovery or client initialization; pure parsing is extracted
  where needed.
- **Object keys are literal:** `%2F` stays three characters.
- **Rust side.** An additive receive method on `ObjectStore` takes a borrowed `&mut [u8]` destination
  and defaults to unsupported, so external implementers (for example, downstream benchmark tools) still compile. A
  default proves no wider compatibility. `LoggedObjectStore` and every wrapper the Python store cache
  uses override and forward it.
- **Errors.** A small shared typed-error and metadata representation, not a new error hierarchy.
  - **S3:** extend `SdkFailure` to keep the status and service code next to its retry verdict, or
    classify at the typed request boundary.
  - **Azure:** reuse `AzureRequestError` and `BlobNotFound`.
  - **GCS:** keep the typed gax status and HTTP status on the new paths.

### 4.2 Writable ownership and completion

1. **Validation.** Accept only a writable, C-contiguous byte export: itemsize 1, format `None`/`B`/
   `b`/`c`. Pointer-bearing or object formats are rejected. `0 <= expected_len <= nbytes`, with
   checked conversions.
2. **Preparation failures** release the export synchronously, then raise.
3. **Handle first.** The guarded completion handle exists before any native write starts. From then
   on, every outcome goes through the handle. PUT's post-spawn wrapper-construction window is not
   reproduced.
4. **Exclusive use.** Native code has exclusive use of the destination span until terminal. The
   documentation forbids reading, modifying, resizing or reusing it before then. A held export blocks
   resizing; it cannot block a racing writer or DMA.
5. **One barrier.** Success, error, cancellation and retries all converge on the same release
   barrier. Terminal means every native writer has stopped and the export has been released with a
   valid Python token. The existing exit-safe delivery gate and releaser rules apply: the GIL is never
   acquired from an arbitrary native `Drop`.
6. **No detached mutable addresses.** Use structured receive futures and disjoint borrowed slices.
   A child that cannot be cancelled keeps its ownership until it really finishes.
7. **Cancel semantics** match the released `GuardedFuture`. `cancel()` is True while the inner future
   is pending, and the handle then ends cancelled. It is False once the outcome is fixed, and the
   handle then ends with that outcome.
8. **HEAD** has no payload, but uses the same quiescence completion, so callers can bound outstanding
   native work.

"Zero copy" means no extra whole-object allocation or copy between s3dlio and the caller. SDK and
network chunks are still written into the final destination. GET must not use `get()` plus a copy,
a zero-filled full-size master buffer, or `ReadBuffer` accumulation plus a copy.

### 4.3 Providers

| Provider | Receive and consistency | Metadata and errors |
|---|---|---|
| **S3** (AWS and S3-compatible, including GCS's S3 endpoint) | Covers all three routes: global-client small GET, concurrent ranges, per-endpoint clients. Streams chunks into the destination. **Range fan-out:** a fresh HEAD on every call, ignoring the size cache, for size and ETag; `If-Match` on every range and retry; each retry's cursor reset; returned range bounds and total validated; a 412 fails the logical read. **No usable ETag from that HEAD:** one GET, pinned to its first-response ETag for any retry; a known size mismatch is still an error. **If that first response also carries no ETag,** a partially received request fails; a retry is allowed only before any byte has been written. | Keeps HTTP status and service code. Tells typed absence apart from 403, throttling, transport and server errors. ETag is opaque, not assumed to be an MD5. |
| **Azure Blob** | **`expected_len > 0`:** one bounded range `0..expected_len` with `partition_size = expected_len` and `parallel = 1`. That takes the SDK's no-remaining-ranges path, which returns the body directly with no partition buffers. The whole size comes from the `Content-Range` total, parsed by s3dlio (the SDK type is crate-private), or from `Content-Length` on a 200; it is checked before any copy. A checked stream-to-slice loop then updates progress after each copy and checks the exact count. **`expected_len == 0`:** a bounded `0..1` request. An empty blob gives 416, retried unranged, then 200 with length 0: success. A non-empty blob is a `LengthMismatchError`. **Retries** keep the first ETag or version. | Reuses `AzureRequestError`/`BlobNotFound`. A missing container is an error, not absence. Credential-mode diagnostics and SAS redaction are kept. |
| **Native GCS** | The HTTP read, gRPC read and tail-repair paths write at checked offsets in the caller buffer. The first response's generation is kept, with `set_generation` (present on both read builders in the pinned fork) on every retry and repair. **Rapid buckets:** `get_into` works through the existing Rapid-aware gRPC read and tail-repair routes. Only the s3dlio-internal sink changes, from `ReadBuffer` to the caller slice. No SDK or fork change is needed: `open_object` has `set_generation`, and tail repair already reads a segment. The Rapid SDK and write-path work stay out of scope. | Keeps typed gax and HTTP status. Only 404/`NOT_FOUND` means absence; GCS cannot tell an absent bucket from an absent object, and this is documented. Generation is exposed as `version_id`. This needs a new field: `GcsObjectMetadata` has none today. Both `get_object_metadata` and the Rapid bidi stat can supply it. Signed sizes are validated before conversion. Rapid-aware metadata keeps its existing route. |

**SDK feasibility, checked in the locked sources:**
- AWS GetObject has `if_match` (`aws-sdk-s3` 1.137.0).
- Azure `azure_storage_blob` 1.0.0 exposes `range`, `parallel`, `partition_size` and `if_match`. Its
  body is a public stream; `collect_into` loses the partial count on error
  (`typespec_client_core` 1.1.0, `response.rs:340–355`).
- The pinned Google fork has `set_generation` (`storage/read_object.rs:185`,
  `storage/open_object.rs:142`) and typed status accessors.
- Google's XML API documents `Range`, `If-Match` and 412 for GETs.

**No public "If-Match HEAD" is needed.** HEAD supplies size and identity; the conditional GET is what
prevents mixed data. A caller's lookup cannot bind a later GET to its version, so each logical GET
establishes and enforces its own.

### 4.4 Logging and byte counts

- New GET and HEAD calls go through the cached store and logger. The wrapper forwards the receive
  method explicitly, so a trait default can never make a logged store look unsupported or skip the
  log.
- **One logical GET is one GET row**, including after a failure or cancellation once native work has
  started, with the actual outcome. Internal ranges, retries and size-probe HEADs are not extra rows.
  An explicit `head_async` is its own HEAD row.
- **The byte count** is the distinct destination positions filled. Each fixed, disjoint span keeps a
  high-water mark, and the marks are summed, so a retried span is not counted twice. Progress
  survives errors and cancellation. On failure the count says which positions were touched, never
  that the data is valid.
- The TSV/zstd schema and the row-ownership rules are unchanged. These rows are logical calls, not
  an HTTP/RPC request trace.

## 9. Acceptance gates

### Lifetime and correctness

- **Lengths and buffers:** exact, short and long objects; a zero-length destination and object;
  malformed lengths; non-contiguous, read-only and wrong-format exporters; checked overflow; canaries
  beyond `expected_len`. A failure never publishes partial contents.
- **No extra copy:** the destination address equals the caller allocation's address; allocation size
  is checked, not padded capacity. No second full-object allocation, zeroing pass or SDK partition
  accumulation on any supported path.
- **Writes and cancellation:** held native writes; partial receive failure; retries; cancellation
  before the first poll, during receive and after the result is fixed; repeated `Task.cancel`,
  `wait_for` and `asyncio.timeout`. The export is released before every terminal state, including
  preparation and launch failures and an already-terminal handle.
- **PUT regressions:** the release-barrier and atexit tests stay green.
- **Python versions:** CPython 3.11–3.13. No free-threaded or wider claim without separate
  verification.
- **Capabilities:** with credentials absent and client construction forbidden, nothing reaches a
  provider. Compiled-out and unsupported providers report False.

### Providers

- **Error classes:** typed absence versus forbidden, throttling, transport and server failures. A
  missing Azure container is not object absence. Zero, negative or missing sizes are checked
  explicitly, with no `unwrap_or(0)`.
- **S3:**
  - the first-response ETag;
  - a fresh HEAD per range call despite a warm or stale size cache;
  - `If-Match` on every range and retry; a 412 and a missing ETag handled;
  - range header validation;
  - a same-size overwrite during fan-out;
  - retry cursor reset;
  - endpoint routing, with no global-client leakage.
- **Azure:**
  - exact, oversized and undersized blobs;
  - 200 and 206 lengths; the empty-blob 416;
  - ETag consistency;
  - checked-loop counts on short, overflow, error and cancellation;
  - the no-remaining-ranges path verified by allocation inspection, not only by the options.
- **GCS:**
  - HTTP and gRPC receive;
  - a partial read plus tail repair;
  - a same-size overwrite, with generation reuse;
  - Rapid-aware metadata, including empty objects;
  - Rapid-bucket `get_into` works through the existing route, including tail repair with the
    generation pinned.

  The fork pin is unchanged.
- **Every provider:**
  - PUT from real caller memory, HEAD, GET into another real allocation, then byte comparison;
  - exact DELETE and already-absent DELETE;
  - keys with literal `%2F`, `%`, `@`, `=`, nested prefixes and a trailing dot;
  - no listing used to find objects.
- **Logging on and off:** exactly one logical GET or HEAD row, the correct outcome and count on
  partial failure and cancellation, and no duplicate helper rows. Existing PUT and DELETE logging is
  preserved.

### Build and release

- **Pre-push gate** (CLAUDE.md), all clean:
  - `cargo fmt --all -- --check`;
  - `cargo clippy --lib --bins --examples -- -D warnings`;
  - `cargo test --lib`;
  - the same clippy and test runs with `--features extension-module`, since `src/python_api/`
    changes.
  - Zero crate-local warnings, and no underscore-prefix silencing.
- **Before any PR** (CLAUDE.md):
  - the wheel built with `./build_pyo3.sh`;
  - `uv run pytest` of the in-repo suite against that wheel;
  - for `python/` changes: `ruff check python/`, `ruff format --check python/`, and
    `uv run python -m compileall -q python/s3dlio python/tests`;
  - a live `mlp-storage` smoke run (`storage_library=s3dlio`, the small UNet3D config) against a
    local S3-compatible target with the candidate wheel installed. CLAUDE.md calls this strongly
    recommended; it is required here, because the round changes the FFI boundary.
- **Rust checks:** formatting, clippy, and unit and targeted integration tests for the default,
  extension-module and full-backend builds. The Arrow library is checked separately if shared
  interfaces change. Never `--all-features`.
- **Wheels:** `./build_pyo3.sh` builds them, and the installed wheel is what gets tested, with the
  imported path, version and features recorded (ephemerally) to rule out source shadowing. Every
  Python command runs through `uv run ... python`.
- **Baseline:** if the whole suite is not green, baseline failures are re-established against 0.9.128
  in the same environment and compared by test identity and reason. A skipped cloud test never counts
  as provider validation.
- **Capabilities by build:** the default wheel reports S3 and Azure; the full build also reports
  native GCS. x86_64/aarch64 and CPython 3.11–3.13 packaging are kept.
- **After functional approval:** caller-buffer GET is measured against the existing allocating GET at
  identical sizes and concurrency, including memory and GIL progress. Destination memory is kept
  separate from staging, and request concurrency from range fan-out. No hardware-specific default is
  introduced.
